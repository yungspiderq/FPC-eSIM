# 📡 eSIMShop — автовыдача eSIM через DesslyHub

Плагин для [FunPay Cardinal](https://github.com/sidor0912/FunPayCardinal) **v0.1.17+**

**Автор:** yungspider

Покупатель оплатил лот с eSIM (Турция, Европа, весь мир…) — плагин сам покупает eSIM-профиль
через API [DesslyHub](https://desslyhub.com/ru) v2 и мгновенно отправляет покупателю всё
для активации: QR/LPA-строку, ICCID, SMDP+ и прямые ссылки установки для iPhone и Android.

> ⚠️ eSIM доступен **только в новом поколении API v2** — нужны и API-ключ, и секретный ключ
> (HMAC-подпись). Если задан только apikey, плагин честно сообщает, что нужен секрет.

## Как это работает

```
новый заказ FunPay
      ↓
привязка лота: «eSIM Турция 5GB» → variant_id + product_id
      ↓
проверки: баланс DesslyHub, остаток (stock), лимит на заказ (max_per_order),
          лимит стоимости, минимальная маржа, ЧС
      ↓
покупка: POST /api/v1/orders (service_type: esim)  → order_id
      ↓
опрос заказа             → success: service_result {iccid, matching_id, qr_code_text,
      ↓                             smdp_address, universal_link, android_universal_link}
покупателю: QR/LPA + ICCID + ссылки установки iOS/Android · error → алерт продавцу
```

## Возможности

- 📡 **Полный цикл по API DesslyHub v2**: каталог eSIM (курсорные страницы) → вариант и
  продукты (цена, остаток, лимит на заказ) → покупка (`esim`) → опрос заказа → выдача
  QR/LPA-данных покупателю.
- 🗺 **Каталог с навигацией по страницам прямо в меню**: варианты (страны/регионы/пакеты),
  продукты с ценой и остатком, готовые строки привязок.
- 🔗 **Привязка лотов через меню**: `Название лота | variant_id | product_id`.
- 📦 **Контроль остатков и лимитов**: `stock = 0` или превышение `max_per_order` —
  заказ не выполняется, деньги не тратятся, продавец получает уведомление.
- 📲 **Покупателю уходит всё нужное**: QR/LPA-строка для ручной установки, ICCID, SMDP+,
  код активации и прямые ссылки установки для iOS и Android.
- 🧪 **DRY-RUN по умолчанию** — весь сценарий проходит, но покупка **не совершается**.
- 🛡 **Защита денег**: порог баланса, лимит стоимости, минимальная маржа, **ровно одна
  покупка на заказ**, состояние переживает рестарт Кардинала.
- ⚠️ **Сообщения об ошибках DesslyHub на русском**; при `failed`/`cancelled` деньги
  возвращаются на баланс автоматически.
- 🔁 **Сетевые сбои ретраятся**, бизнес-ошибки — нет.
- 📋 Меню `/esim`: баланс, каталог eSIM, привязки, история, лимиты, тексты сообщений.

## Установка

```bash
cd /home/fpc/FunPayCardinal
wget https://raw.githubusercontent.com/yungspiderq/FPC-eSIM/main/esim_shop.py -O plugins/esim_shop.py
sudo systemctl restart FunPayCardinal@fpc
```

или отправьте файл боту в Telegram → `🔌 Плагины` → `➕ Добавить плагин`.

> ⚠️ Лоты с eSIM **не должны** быть в `configs/auto_delivery.cfg` — иначе Кардинал выдаст
> товар сам.

## Первый запуск (по шагам)

1. `/esim` → **🔑 API-ключ** и **🔐 Секрет** — для eSIM нужны оба (API v2). Выдаёт менеджер
   DesslyHub ([@DesslyHub_Manager](https://t.me/DesslyHub_Manager)).
2. **🧪 Тест подключения** — убедитесь, что определился режим `v2`, виден баланс и курс RUB.
3. **📡 Каталог eSIM** — листайте страницы вариантов (страны/пакеты), откройте вариант:
   увидите продукты с ценой, остатком и готовой строкой привязки.
4. **📦 Привязки лотов → ➕ Добавить**:
   ```
   eSIM Турция 5GB | var-123 | prod-456
   ```
5. Сделайте **тестовый заказ**, оставив **DRY-RUN включенным**: придет карточка
   «что было бы куплено» — вариант, продукт, цена.
6. Проверьте карточку и только затем **выключайте DRY-RUN** и включайте плагин.

## Использование

Команда **`/esim`** (или `⚙️ Настройки` на странице плагина):

| Кнопка | Действие |
|---|---|
| 🔴 Включить / 🟢 Выключить | Master-switch автовыдачи |
| 🧪 DRY-RUN: ВКЛ/ВЫКЛ | Тестовый режим: всё считается, но покупка не совершается |
| 🔑 API-ключ / 🔐 Секрет (v2) | Ввести ключ и секрет DesslyHub (в меню маскируются) |
| 💳 Баланс | Всего / доступно / резерв / овердрафт мерчанта DesslyHub |
| 🧪 Тест подключения | Поколение API + баланс + курс RUB |
| 📡 Каталог eSIM | Страницы вариантов → продукты (цена, остаток), строки привязок |
| 📦 Привязки лотов | Список, ➕ добавление, 🗑 удаление |
| 🧾 История операций | Последние заказы: статус, продукт, цена, ICCID, текст ошибки |
| 🔄 Проверить транзакции | Немедленно опросить статусы всех активных заказов |
| 🛡 Лимиты и защита | Лимит покупки, порог баланса, маржа, валюта FunPay |
| 💬 Тексты сообщений | Текст выдачи eSIM, текст при ошибке |
| 🌐 API: auto/legacy/v2 | Переключение поколения API (для eSIM нужен v2) |

### Текст выдачи по умолчанию

```
📡 Ваша eSIM готова: $esim_name

🔳 QR/LPA для ручной установки:
$qr

📲 Быстрая установка:
• iPhone/iPad: $ios_link
• Android: $android_link

ICCID: $iccid
SMDP+: $smdp  •  код: $matching

Устанавливайте eSIM заранее, до поездки, и не удаляйте профиль до конца действия пакета.
Спасибо за покупку, $username! Будем рады вашему отзыву ⭐
```

Переменные плагина: `$order`, `$esim_name`, `$qr` (LPA-строка `LPA:1$…`), `$iccid`, `$smdp`,
`$matching`, `$ios_link`, `$android_link`; плюс переменные Кардинала (`$username`,
`$order_desc`, …). При ошибке покупателю по умолчанию **ничего не отправляется**
(`failed_text` пустой).

## Настройки

`storage/plugins/esim_shop/settings.json` — можно править руками (перечитывается при каждом
обращении) или через меню `/esim`.

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | master-switch: обрабатывать ли заказы |
| `dry_run` | `true` | тестовый режим — покупка не совершается |
| `apikey` / `secret` | `""` | ключ DesslyHub и секрет для API v2 (HMAC) — нужны оба |
| `api_mode` | `auto` | `auto` / `legacy` / `v2`; legacy для eSIM не поддержан (`-5`) |
| `base_url` | `https://desslyhub.com` | адрес API |
| `timeout` / `retries` | `20` / `2` | таймаут запроса и число повторов при сетевом сбое |
| `ask_for_data` | `true` | (не используется — данные покупателя не нужны) |
| `success_text` | см. выше | сообщение покупателю с данными активации |
| `failed_text` | `""` | сообщение покупателю при ошибке (пусто = не отправлять) |
| `poll_interval` | `10` | интервал опроса статусов заказов, секунд |
| `poll_max_minutes` | `90` | после этого заказ считается «зависшим» → алерт |
| `min_balance_usd` | `5` | порог баланса DesslyHub (ниже — не покупаем + алерт) |
| `max_order_cost_usd` | `100` | лимит стоимости одной покупки |
| `min_margin_percent` | `0` | минимальная маржа, `0` = проверка выключена |
| `funpay_currency_code` | `5` | код валюты цены заказа (5 RUB, 1 USD, 3 EUR, 18 UAH, 37 KZT) |
| `notify_low_balance` | `true` | уведомление в Telegram о низком балансе |
| `low_balance_repeat_minutes` | `60` | пауза между повторными алертами, минут |
| `mappings` | `{}` | привязки лотов: `{ "название лота": {"variant_id":…, "product_id":…} }` |
| `catalog_cache_minutes` | `720` | время жизни кэша каталога |

Данные: `storage/plugins/esim_shop/orders.json` (журнал заказов),
`storage/plugins/esim_shop/catalog.json` (кэш каталога).

## Важно знать

- **Только API v2.** В legacy-поколении eSIM нет: при попытке купить с одним apikey заказ
  помечается ошибкой `-5` («нужен секретный ключ v2»), деньги не тратятся, приходит алерт.
- **Деньги.** Покупка — только при выключенном `dry_run` и после всех проверок. На один
  заказ — ровно одна покупка: дубли событий и перезапуски не приводят ко второму списанию.
- **Перезапуск во время покупки.** Заказ помечается `error` и приходит алерт — автоматически
  повторять нельзя. Проверьте заказы DesslyHub: если eSIM купилась, данные активации
  (`service_result`) можно взять оттуда и выдать вручную.
- **Остатки и лимиты.** Перед покупкой проверяются `stock` и `max_per_order` продукта.
  `stock = 0` → `failed` без трат; превышение лимита → понятная ошибка продавцу.
- **Одноразовость QR.** LPA-строка и QR действуют ограниченное время и привязаны к одному
  устройству; если покупатель не установил профиль вовремя — решается через DesslyHub
  (повторная выдача/возврат), а не повторной покупкой.
- **API-ключ и секрет** хранятся только на вашем сервере в `settings.json`, в меню
  показываются маскированными, в логи не пишутся и никуда не передаются, кроме `desslyhub.com`.

## Используемые методы API DesslyHub

| Метод (v2) | Зачем |
|---|---|
| `GET /api/v1/catalog/esim/products` | страницы вариантов каталога (курсор) |
| `GET /api/v1/catalog/esim/products/{variant_id}` | продукты варианта: цена, stock, max_per_order |
| `POST /api/v1/orders` (`service_type: esim`) | покупка (`reference` = номер заказа) |
| `GET /api/v1/orders/{order_id}` | опрос статуса; данные в `service_result` |
| `GET /api/v1/balance` | баланс мерчанта |
| `GET /api/v1/currency/exchange_rates/steam/{code}` | курс для маржи |

Документация: [desslyhub.readme.io](https://desslyhub.readme.io/reference/introduction),
коды ошибок: [error-codes](https://desslyhub.readme.io/reference/error-codes).

## Состав репозитория

- `esim_shop.py` — плагин (класть в `plugins/`).
- `tests_plugin_esim_shop.py` — тесты (**89 проверок** на моках: метаданные, настройки,
  авторизация legacy+v2 (HMAC), автоопределение API, ретраи, хранилище, весь Telegram-UI,
  привязки, отказ legacy (`-5`), полный цикл v2 (LPA/ICCID/ссылки, сумма списания),
  `stock = 0`, превышение `max_per_order`, DRY-RUN, денежные защиты, идемпотентность,
  восстановление после перезапуска, поллер и таймауты, каталог с курсорной пагинацией и
  карточкой варианта, удаление плагина). Запуск из корня FunPayCardinal:
  ```bash
  cp tests_plugin_esim_shop.py /path/to/FunPayCardinal/
  cd /path/to/FunPayCardinal && pip install -r requirements.txt && python3 tests_plugin_esim_shop.py
  ```
  Тесты создают настройки во временной папке — ваши реальные `storage/plugins/esim_shop/`
  не затрагиваются, запросов в интернет нет.
